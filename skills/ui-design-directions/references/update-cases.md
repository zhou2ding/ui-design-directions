# 怎样从新的 X 转发更新案例库

当用户说有新转发、提供帖子，或要求更新案例库时执行一次。正常设计任务直接读取已有案例库。

1. 从用户给的帖子开始。用户指向自己的转发时，使用其授权的已登录浏览器查看公开转发。打开原帖和作者链接的演示或项目。无法访问时请用户发公开链接或截图。只有截图时标明观察范围，等找到可公开引用的原作再收录。
2. 区分作品作者、转发者和整理工具的人。保留原帖的规范链接 `https://x.com/作者/status/帖子ID`，去掉分享参数。同一作品的原文、演示、仓库放在同一行。按帖子 ID 和项目地址去重。
3. 给候选案例写下一条可以从画面复核的做法，如「打开筛选后，已选条件仍留在结果旁」，再写它适用的页面或控件。纯宣传、没有演示或重复已有做法的帖子可以略过。将桌面软件截图、静态概念图和可操作作品区分清楚。
4. 将新作品加入同目录的 `x-cases.md`。有独立产品页且能补充一个新问题时，才在 `cases.md` 增加入口。遇到失效链接，优先找作者的公开原作。无法核实时标注状态。新发现的工具在核实上游仓库、Skill 名称与依赖后才写入 `tools.md`。
5. 在案例库的可写源码仓库内修改，复查链接和 diff。向用户列出新增、合并或暂缓的案例及理由。对外发布沿用用户给出的仓库与授权范围。公开记录只放作品来源和设计观察，登录信息、私人收藏路径和账号浏览记录留在本地。

一条足够具体的记录可以参照下表。

| 作者与作品 | 可核对的细节 | 适合借鉴的情况 |
| --- | --- | --- |
| 作者原帖和公开演示链接 | 选择一组数据后，图例和曲线同时强调该组，旁边的读数保留单位 | 数据分析面板需要让读者在图表和数字之间建立对应关系 |

上表最后一行仅示范写法。将新作品录入索引时使用其真实作者、链接和观察。
